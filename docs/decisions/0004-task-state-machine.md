# ADR 0004: 先实现纯 C++ 抓取任务状态机

## 决策

阶段 4 新增 `edgepick_task` 包，并先实现无 ROS 依赖的 `GraspStateMachine`。状态机覆盖感知、规划、执行、验证、恢复、成功、失败和取消，不直接调用 MoveIt、相机或真实机械臂。

## 背景

EdgePick 的核心价值不是“识别到目标后发送固定舵机角度”，而是把失败、超时和恢复做成可诊断的任务流程。这个流程如果一开始就和 ROS action、相机回调、MoveIt 结果混在一起，会很难单元测试，也很难在面试中解释清楚。

## 后果

- `edgepick_task` 现在可以在无 GUI、无相机、无机械臂的环境里测试。
- 后续 ROS 2 节点只需要把外部事件翻译成 `TaskEvent`。
- 恢复预算、失败码和状态字符串先稳定下来，方便后续 diagnostics 和实验记录复用。

## 结构反思

阶段 4 的边界是正确的：`edgepick_hardware` 处理硬件安全门，`edgepick_bringup` 处理启动编排，`edgepick_task` 处理任务决策。三者互不替代，后续扩展不会把感知、规划和硬件写入混成一个节点。

## 当前阶段

阶段 4：抓取任务状态机核心已实现并通过单元测试。

## 下一步

阶段 5：新增 ROS 2 task node，接收 mock 感知/MoveIt/验证事件，发布任务状态和失败原因。
